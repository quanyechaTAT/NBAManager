# 数据同步中心

## 任务流程

手动单模块、定时任务和补偿任务经 `SyncCoordinator` 提交，复用同一模块的活动任务。
全量同步顺序执行九个模块，以父任务和子步骤记录进度、结果；与单模块任务互斥。
取消请求由后端确认，从 `QUEUED/RUNNING` 进入 `CANCELLING`，最终进入终态。

## 状态与展示

`GET /api/admin/overview` 是同步中心的状态快照，包含模块计数、单模块最新/活动任务、
活动全量父任务、最新全量任务及步骤、模块最近成功时间。
最新任务与最近成功任务通过按模块排序的窗口查询批量读取，避免对每条历史记录重复扫描。
最近成功时间取单独同步与全量步骤的最新成功记录，失败和取消不会覆盖它。
已结束的全量步骤与单模块最新任务按执行时间比较，避免旧任务覆盖新结果。
父任务结束后，未结束的步骤显示为取消或中断，保留数据库原始记录。

前端 `useSyncCenter` 管理所有请求和任务状态。提交/取消请求的等待状态与后端任务状态独立，
接口失败不会生成虚假的失败任务。全量任务可以从快照直接恢复，避免依赖最近 100 条历史。
单模块允许独立提交；“重试失败模块”只重新提交失败、部分失败或中断的模块。

活动任务每 3 秒刷新，空闲时每 15 秒检查新任务。概览查询串行执行，命令提交后丢弃旧快照。
查询设置 15 秒超时；网络失败保留最近快照并提示重试。离开页面时清理定时器和中止查询。
历史和详情查询使用请求序号，避免旧响应覆盖新筛选结果。
任务完成后，包括全量同步的成功步骤，会发送数据刷新通知。

## 验证

`DataSyncView.test.ts` 覆盖请求防重、后台任务发现、取消竞态、失败重试、网络恢复、
历史响应交错、全量完成通知及页面卸载。后端概览测试覆盖全量结果与最近成功时间；
`SyncSnapshotRepositoryTest` 使用独立 H2 内存数据库验证批量查询与时间并列的选择规则。

2026-10-06 本地验证（约 3,000 条任务记录）：概览从 9,293 毫秒降至三次实测的
86、70、74 毫秒。真实全量任务在执行中的第一步取消后，父任务和九个步骤均为已取消，
执行中的步骤保留 10% 进度，其余未开始步骤为 0%。验证不要求外部数据源完成全量抓取。

## 2026-10-13 同步执行修复

- 球员与比赛任务分别调用 `players`、`games`，不再误执行 `all`；超时使用统一的 `bulk-seconds` 配置。
- 球员基础与高级统计保持原接口，个人资料改为 `PlayerIndex` 一次批量获取，避免数百次串行 `CommonPlayerInfo` 请求。姓名使用已有映射，待翻译项由翻译模块处理；统计刷新保留数据库已有译名。
- `sync_network.py` 为 NBA Stats、NBA Live 与 urllib 来源统一提供显式代理、直连回退和一次有界重试。关闭代理时不继承 Windows 系统代理，也不修改全局环境变量。
- 比赛逐日失败会返回 `failed` 或 `partial`，不会把来源异常当成没有比赛。选秀快照回退标为 `stale`，空结果判为失败。
- 季后赛刷新真实来源，比分优先采用 NBA `LeagueGameFinder` 批量结果；ESPN 回退按日请求，避免日期区间 HTTP 400。来源不完整时保留已有对阵，展示优先使用同步后的数据库记录。季后赛调度修正为 4—6 月每两小时。
- 翻译模块传播子进程失败，未成功条目可再次重试；选秀、历史赛季与翻译任务上报实际处理数量。
- 僵尸任务恢复先无锁选取候选，再按主键逐项检查心跳并更新，避免状态索引范围更新与工作线程互相死锁。终态任务不再重新进入运行态。
- 无效/过期登录返回 401；权限不足仍返回 403。前端 401 跳转至 `/#/login`，兼容 `/login#/admin/sync` 旧地址。
- 全量步骤的结果独立显示；成功步骤不会继承之前单模块任务的失败原因。
